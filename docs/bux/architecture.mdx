This page is for users who want to know what's running inside a BUX VM and how to deploy it themselves.

## VM lifecycle

<Steps>
  <Step title="Provision">
    The control plane launches an EC2 instance from a prebaked AMI containing Claude Code, Browser Harness, Chrome, and the BUX agent.
  </Step>
  <Step title="Boot">
    On first boot, the VM contacts the control plane to fetch its assigned identity, your Telegram bot token, and any profiles you've attached. Boot completes in 30 to 60 seconds.
  </Step>
  <Step title="Run">
    Claude Code runs inside a `tmux` session reachable from Telegram, the web terminal, and SSH simultaneously.
  </Step>
  <Step title="Hibernate or destroy">
    Idle VMs are hibernated after 24 hours and resumed on the next message. Destroying a BUX wipes the EBS volume.
  </Step>
</Steps>

## Isolation

Each BUX is a dedicated VM. There is no multi-tenancy at the OS level, so one user's tasks cannot read another user's profiles, cookies, or terminal output.

## IAM posture

The BUX instance role is **deliberately empty**. It cannot:

- Read or write S3, DynamoDB, or any other AWS service.
- Describe its own EC2 metadata beyond the bare minimum needed to boot.
- Assume any other role.

If a task somehow tricked Claude Code into running `aws ...`, every call would fail with `AccessDenied`. The control plane is the only component with AWS permissions, and it sits on a separate network.

## Network

Outbound is open so the agent can browse the web and reach the Anthropic API. Inbound is limited to:

- The web terminal proxy (TLS, authenticated by your Browser Use session).
- SSH, restricted to the key pair generated when you created the BUX.
- The live browser URL, which is a short-lived WebRTC offer signed by the control plane.

## Data at rest

- **Profiles** are encrypted with a per-account key managed by AWS KMS.
- **Conversation history** lives on the VM's EBS volume and is destroyed when you delete the BUX.
- **Telegram messages** are stored by Telegram, not by Browser Use. We only see them in transit through the bot API.

## Self-hosting

The VM image, control plane, and Telegram bridge are open source. Clone the repo and follow the README to deploy BUX in your own AWS account:

```bash
git clone https://github.com/browser-use/bux
cd bux
make deploy AWS_REGION=us-east-1
```

You'll need an Anthropic API key, an AWS account with permission to create EC2 + KMS resources, and a Telegram bot token. Self-hosting means your profiles and logs never leave your account.
